## 2. 场景 02｜赋值语义图解（≈60s）

- **画面**：
  - 左侧：`a = a + 3` 的代码块。
  - 右侧：三步拆解动画——
    1. 读旧 a（=2）→ 用淡灰框圈出。
    2. 算右侧 2+3=5 → 用蓝色框圈出。
    3. 写回 a=5 → 左侧 a 的值从「2」翻牌为「5」。
- **旁白**：
  > 「=」不是方程，是单向动作：先算右边，再把结果写回左边。
  > 所以 `a = a + 3` 这一行：先读旧 a 等于 2，算出右边是 5，再把 a 改成 5。
  > 关键点：右边看到的是旧值，写回之后才有新值。
- **板书口诀**：「右读旧 · 左写新」。
- **可选动画**：第 3 步后让 a 的旧值「2」淡出，新值「5」淡入。

## 3. 场景 03｜三条心法（≈30s）

- **画面**：三行并排卡片。

## 4. 场景 04｜精讲 ① 单变量自更新（≈70s）

对应 `fixture-final-q-1`。

- **代码**：
  ```cpp
  int a = 2; a = a + 3; cout << a;
  ```
- **答案**：`5`
- **节奏**：
  1. **预测（15s）**：停顿，显示「先猜猜看：执行到 `cout << a` 时 a 是几？」。
  2. **逐行揭示**：
     - 第 1 行：`int a = 2;` → a=2
     - 第 2 行：`a = a + 3;` → a=5（旧 2 + 3）
     - 第 3 行：`cout << a;` → 输出 `5`
  3. **状态表**：呈现 3 行 × 3 列；第 2 行 a 单元格用「旧 2 → 新 5」标记。
- **旁白**：
  > 第一行把 a 初始化成 2。
  > 第二行进入关键：右边读到的是旧 a 等于 2，算出 2+3=5，再写回 a。
  > 所以第三行输出 5。
- **纠错点**：强调「= 不是方程」，「右侧用旧值，写回是新值」。
- **资产建议**：状态表用 CSS Grid，单元格切换时短暂黄色高亮 400ms 后保持稳定高亮。

## 5. 场景 05｜精讲 ② 双变量顺序依赖（≈75s）

对应 `fixture-final-q-2`。

- **代码**：
  ```cpp
  int x = 4; int y = x + 2; x = y - 1; cout << x;
  ```
- **答案**：`5`
- **节奏**：
  1. **预测（15s）**：提示「重点想：y 的值什么时候被 x 决定」。
  2. **逐行揭示**：
     - 第 1 行：x=4
     - 第 2 行：y = x + 2 = 4 + 2 = **6**（x 还是 4）
     - 第 3 行：x = y - 1 = 6 - 1 = **5**（y 已经是 6）
     - 第 4 行：输出 `5`
  3. **状态表**：4 行 × 4 列。
- **旁白**：
  > 第二行 y 看到的是旧 x 等于 4，所以 y 变成 6。
  > 第三行反过来：x 看到的是刚刚写好的 y 等于 6，所以 x 变成 5。
  > 顺序很重要——后执行的语句能读到前一句的新值。
- **板书口诀**：「行行接力，前写后读」。
- **资产建议**：x、y 两个变量分别用蓝色与粉色色块；写到第几行就在那一行的对应单元格闪一下。

## 6. 场景 06｜精讲 ③ 临时变量交换（≈85s）

对应 `fixture-final-q-7`。

- **代码**：
  ```cpp
  int x = 2, y = 7; int t = x; x = y; y = t; cout << x << y;
  ```
- **答案**：`72`
- **节奏**：
  1. **对照演示（20s）**：先演示「错误版本」——`x = y; y = x;` 会让两个变量都变成 7，打印 `77`。提示「为什么？因为旧 x 没保存，被覆盖了」。
  2. **逐行揭示正确版本**：
     - 第 1 行：x=2, y=7
     - 第 2 行：t = x = 2（**旧 x 已拍照**）
     - 第 3 行：x = y = 7
     - 第 4 行：y = t = 2
     - 第 5 行：输出 `72`
  3. **状态表**：5 行 × 5 列；t 那一列在第 2 行后保持 2。
- **旁白**：
  > 想要交换两个变量，必须先把其中一个的旧值「拍张照片」存起来——这就是临时变量 t 的角色。
  > 三步走：先把 x 存进 t，再把 y 写给 x，最后把 t 写给 y。
- **板书口诀**：「要交换，先借 t——t = x → x = y → y = t」。
- **互动彩蛋（可选）**：让一只小动画「备忘录卡片」在第 2 行飞到 t 那一格，里面写着「旧 x = 2」。

## 7. 场景 07｜互动抽测 ①（≈55s）

对应 `fixture-final-q-3（旧值混淆陷阱）`。

- **代码**：
  ```cpp
  int a = 3, b = 5; a = b; b = a + 2; cout << a << b;
  ```
- **答案**：`57`
- **节奏**：
  1. **预测（15s）**：「抢答：先猜 57 还是 75？」
  2. **揭示**：逐行点亮；强调「`a = b` 之后，a 已经是 5；下一行 `b = a + 2` 里的 a 也是 5，不是旧 3」。
  3. **状态表**：4 行 × 4 列。
- **旁白**：
  > 容易踩的坑：以为 `a = b` 之后 b 还会跟着 a 变。
  > 实际上赋值是「快照」——赋值的那一刻，旧 b 的值被复制给 a，b 自己不动。
- **板书口诀**：「赋值是快照，不是订阅」。

## 8. 场景 08｜互动抽测 ②（可选，≈45s）

对应 `fixture-final-q-4（链式自更新）`。

- **代码**：
  ```cpp
  int x = 1; x = x + 1; x = x * 3; cout << x;
  ```
- **答案**：`6`
- **节奏**：
  1. **预测（10s）**：「第 3 行的 x 起点是 1 还是 2？」
  2. **揭示**：第 2 行 x=2；第 3 行读到这个新 2，得 2×3=6。
  3. **状态表**：4 行 × 3 列。
- **旁白**：
  > 右侧永远读「上一行的最新值」，不读最初的 1。
  > 这是迁移到「更长程序片段」的关键。

> 备注：本场景为可选；若总时长偏紧，可裁掉，但建议保留至少一道互动抽测以巩固「快照 / 接力」概念。
